# 精修与扩写（一键去味流水线 · 章节精修模式 · 有效扩写）​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

> 本文件由 SKILL.md v1.5.3 拆分迁入（原行号 1497-1708），内容未改动，仅标题层级与衔接处微调。

## 一键去味流水线（精修 → 去AI味 → 回归校验）​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

### 触发​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

用户说「一键去味」「完整流水线」「跑全套」「精修+去味」时触发。只跑一章，不自动续写。默认关闭，不自动触发。

### 第 0 步：定三格（不占步号，精修前跑完；仅叙事文本）​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

- 按「熊 AI 走」`novel_optional/narrator_position.md` 从原稿反推三格（谁在说／对谁说／为什么说），写一句定位。
- **一个字都不动**，也不产出正文；只产出定位结论，写进最终报告。
- 三格打架处只标注、请作者定主线，不代选。
- 非叙事文本、或原稿短于 100 字 → 跳过，报告写「未定位：原因」。
- 三步顺序锁（精修 → 去AI味 → 回归校验）**不变**；定位在三步之前跑完，不占步号、不属于三步。

### 三步固定顺序（不得跳步、不得换序）​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

**第一步：精修（含润色）**
- 按「章节精修模式」执行，输出【精修诊断】【精修方案】【逐段精修】【精修对照说明】。
- **本流水线内增幅上限收紧到 ≤20%**（与下方总增幅 30% 回退阈值兼容）；单独「章节精修模式」仍保留手动 20%–50% 档位，两条路径不共用上限。
- 若发现某场景缺「价值转变」或缺「鸿沟」（7.6 新增硬红线），精修有权补——补完在对照说明里单列一条「补价值转变 / 补鸿沟」。
- 产出：精修版正文 + 精修对照说明 + 状态库变更（如有）。

**第二步：去AI味**
- 调用「熊 AI 走」skill，对精修版执行词级、句式级扫描。
- 砍：伪深刻抽象词、伪细腻量词、公式化神态、万金油形容、成语连用 / 成语总结情绪、AI 专属句式。
- 产出两份：去味版正文 + `已砍清单.md`（表格：位置｜原词/原句｜改成｜类型）。
- 去AI味只砍不加，不改情节、不改逻辑、不改人名。
- 调用熊 AI 走 skill 的**小说/叙事分支**（不是通用分支），按其 `narrative_checklist.md` 六层检查表 + `SKILL.md` 二稿自检顺序执行。
- 本 skill 不重复熊 AI 走 skill 的六层检查表；冲突时以本 skill 的闸1/闸2 硬判定为准（见熊 AI 走 skill `adjudication.md` 第 12 条）。
- 去AI味阶段只砍不加；精修阶段可加内容；回归校验只修错。三阶段不混用。

**第三步：回归校验**
- 读去味版 + `已砍清单.md`，只做三件事：修语法错、修事实错、修逻辑错。
- 禁止：修「不够书面」「不够文雅」；把已砍清单里的原词加回来；加同类抽象词；把短句改回因果长句。
- 「小说分段改稿」skill 的 A9（补「而」）、A1（补因果）在本步不执行，被去AI味覆盖。
- 产出：定稿版正文 + 回归校验报告（改了哪几处、为什么、是否触碰已砍清单）。

### 止损规则（最高优先，覆盖三步流程）​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

1. **原稿锚点**：流水线启动前存 `原稿.md`；每步对比原稿，不对比上一步。和上一步比永远「更好了」，和原稿比才看得出是不是真的更好。
2. **不改权**：每一步都可输出「本步不改，保留上一步版本」。判断依据：
   - 精修：逻辑自洽、细节够、节奏稳 → 只出诊断，不出修改。
   - 去AI味：AI 词密度低于阈值 → 只出扫描报告，不逐词替换。
   - 回归校验：无语法错 / 事实错 / 逻辑错 → 输出「无错，定稿」。
   「不改」是合法输出，不是偷懒。
3. **总增幅上限**：原稿 → 定稿，总字数增幅 >30% 或 <-20%，回退到最后一步「不改」的版本；仍异常，回退原稿。
4. **对比报告**：定稿必须附一行「对比原稿」：字数变化、关键改动数、回退项数。
5. **不做也是选项**：若三步诊断都显示「本章无需修改」，输出「建议保留原稿」，不强行改。

> 流水线的目标不是「跑完三步」，是「定稿比原稿好」。跑完三步但定稿更差，是流水线失败，不是成功。

### 冲突裁决表（三步各守各的，不互相覆盖）​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

| 冲突项 | 精修阶段 | 去AI味阶段 | 回归校验阶段 |
|---|---|---|---|
| 「不是…而是…」 | 可用 | 禁止，改直白陈述 | 不许补「而」 |
| 「之所以…是因为…」 | 情节必需可保留 | 砍因果解释 | 不许补因果连接词 |
| 成语 | 单个可用对 | 砍连用两个以上、砍成语总结情绪 | 不许把砍掉的成语加回来 |
| 增幅 | 加内容 | 减字 | 不加字 |
| 环境笔 / 动作笔 | 可补 | 砍公式化环境动作 | 不许把砍掉的加回来 |

### 顺序锁（防回潮，最高优先）​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

1. 三步必须按「精修 → 去AI味 → 回归校验」顺序跑，不得换序。
2. 去AI味跑完，不得回精修加内容；回归校验跑完，不得回去AI味再砍。
3. 每步产出必须落盘：精修版、去味版、已砍清单、定稿版，四份都在，缺一份视为流水线未完成。
4. 若用户中途喊停，停在当前步，输出「流水线暂停于第 X 步」，不自动跳步。

### 与「小说分段改稿」skill 的边界​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

- 本流水线的第三步「回归校验」是**自动跑**的收尾，只修错不修味。
- 「小说分段改稿」skill 是**人工逐段**工具，触发词「这段改」「排一下」，不进本流水线。
- 两者的 B/D 层清单共享，但执行方式不同：流水线第三步批量过，分段改稿逐段过。

### 输出格式​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

【一键去味流水线 · 第 X 章】
1. 精修诊断 + 方案 + 对照说明（同章节精修模式）
2. 去AI味报告 + 已砍清单（表格）
3. 回归校验报告（改了哪几处、是否触碰已砍清单）
4. 定稿版正文
5. 【对比原稿】字数：原稿 X → 定稿 Y（±Z%）｜关键改动 N 处｜回退项 M 处
6. 【下一步】询问用户是否接受定稿，或回退某一步重跑

> 若三步中有任一步输出「本步不改」，在对应位置写「本步不改，保留上一步版本」，不强行改。

## 章节精修模式​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
### 触发条件​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
当用户说「精修第 X 章」「润色第 X 章」「填充第 X 章细节」「把第 X 章改好」时，进入本模式。
> **触发词歧义裁决**：用户只说「润色」两个字、未指明章节或段落时，默认进「2500 字小循环第 5 步」（≤15%，只修文字，不补逻辑），不进精修。
> - 「润色第 X 章」→ 精修（20%–50%，补逻辑补细节）
> - 「润色这一段」→ 小循环第 5 步（≤15%，只修文字）
> - 单「润色」→ 小循环第 5 步（≤15%，只修文字）
> 理由：单说「润色」，用户预期通常是「顺一顺文字」，不是「大修」。要补逻辑，用户会说「精修」或「改好」，不会只说「润色」。若用户单说「润色」但实际想补逻辑，AI 应先问一句「只顺文字，还是连逻辑一起补？」，不默认进精修。
### 自动精修开关​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
#### 触发​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
- 开启：用户说「开启自动精修」
- 关闭：用户说「关闭自动精修」
- 默认：关闭

#### 开启后的执行流程​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
每章写后校验完成后，自动执行：
1. **【精修诊断】**：列出本章问题，分类为逻辑、人物、节奏、语言、细节。
2. **【精修方案】**：说明每段打算怎么改，预计增加多少字。
3. **【逐段精修】**：输出精修版正文。
4. **【精修对照说明】**：关键修改点，不超过 10 条。

#### 约束​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
- 不改变核心情节和结局走向。
- 不新增未经用户确认的重大设定。
- 不删除原有伏笔和关键信息。
- 单章精修后字数增幅不超过 20%（低于手动精修的 20%-50%，因为每章都跑）。
- 保持与前后章节文风一致。
- 精修在既成文本中插入/改写后，执行「有效扩写 · 插入改写自洽校验」。
- 状态库、伏笔表、摘要树同步更新。

#### 输出位置​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
~~在【写后校验报告】之后、【下一步】之前，加【自动精修报告】。~~（v1.4.1 起由「对应输出格式第 8.5 项」取代）【自动精修报告】对应「输出格式」第 8.5 项。

#### 用户干预​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
- 「回退本章精修」：撤回本章精修，恢复原稿。
- 「关闭自动精修」：本章剩余不再自动精修。
- 「本章不精修」：只跳过本章。
### 输入​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
用户提供待精修章节原文，或指定状态库中已存在的章节编号。
### 精修目标​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
1. **语言润色**：修正语病、优化句式、统一文风。
2. **细节填充**：补充场景、动作、心理、对话、感官描写，但不注水。
3. **逻辑补全**：修复因果跳跃、人物行为不合理、时间线矛盾。
4. **状态一致**：与状态库、滚动摘要保持一致，不改变核心剧情走向。
5. **伏笔保护**：不误删、不误改已埋伏笔，不提前回收未到期伏笔。
### 工作流程​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
1. 读取状态库精简版 + 相关滚动摘要 + 待精修章节原文。
2. **【逐句改询问】**：询问用户「本章是否需要逐句改台词？」
   - 选是：在精修流程中插入逐句台词确认；精修诊断、精修方案、精修对照说明仍照常输出。
   - 选否：按普通精修流程执行。
3. 输出【精修诊断】：列出原文问题，分类为逻辑、人物、节奏、语言、细节。
4. 输出【精修方案】：说明每段打算怎么改，预计增加多少字。
5. 逐段输出精修版正文，保留原章节编号和标题。
6. 输出【精修对照说明】：关键修改点，不超过 10 条。
7. 若精修涉及人物状态、时间线、伏笔变化，更新状态库并输出【状态库变更】；否则写「无需更新」。
8. 询问用户是否接受精修版，或需要继续调整。
### 约束​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
- 不改变核心情节和结局走向。
- 不新增未经用户确认的重大设定。
- 不删除原有伏笔和关键信息。
- 单章精修后字数增幅建议控制在 20%-50%，避免注水。
  - 例外：若启用逐句改台词且仅替换台词、不新增段落，字数增幅按实际改动计算，不强制套用 20%-50%。
- 精修增幅必须落在「有效扩写」14 个方向内，不得为凑 20%-50% 加无信息量内容；增幅达标但信息密度为零的，按注水退回。
- **三档增幅的设计意图**：手动精修是用户主动触发、单章大动作，允许 20%-50%；自动精修每章都跑、保守为 ≤20%；小循环每 2500 字润色一次、更保守为 ≤15%。粒度越小，增幅越紧，避免累积注水。
- 保持与前后章节文风一致。
- 精修在既成文本中插入/改写后，执行「有效扩写 · 插入改写自洽校验」。
## 有效扩写​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
精修模式、续写、用户要求加字时，AI 按本节执行。核心原则：**扩写不是加字数，是加有效信息密度。每个加进去的字，必须至少服务一项——情节、人物、氛围、伏笔、主题。**

### 插入改写自洽校验（有效扩写·精修·去味通用）​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
在**既成文本**（对白与对白之间、叙述之间）插入或改写后，必须重读**所在场景完整段落**验证自洽：
- **「逐句衔接通顺」≠「同场景自洽」**：插入处前后读着通顺，不代表整场戏逻辑、动作、说话人、视角仍自洽。
- 校验点见「语义/规范硬校验表」：无残句、无动作互斥、无姿势漂移、无视角越界、无说话人悬空、无相邻重复。
- 此项适用于：扩写加字、精修、去 AI 味"降全知"改写、任何在既有段落中间动的操作。
### 什么不算有效扩写（底线）​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
- 重复已写过的信息。
- 大段无信息量的环境/背景描写。
- 堆形容词、堆辞藻，但信息增量为零。
- 用梗、用闲笔填充字数，不服务情节或人物。
- 高潮、反转、死亡等紧凑场景里加闲笔。
> 本节继承「防注水自查清单」与「七维禁止」条款，不绕过。
### 14 个扩写方向​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
| # | 方向 | 具体做法 | 适合指令 |
|---|------|---------|---------|
| 1 | 人物细节 | 外貌、习惯动作、语言指纹、随身物件 | 辞藻、加字数 |
| 2 | 心理层次 | 不是“他生气”，而是愤怒下面的恐惧、犹豫、自我说服。具体执行见「画面感执行纪律」第 1、6 条。 | 润色、加字数 |
| 3 | 人物关系微表情 | 眼神、距离、身体朝向、称呼变化。具体执行见「画面感执行纪律」第 1、8 条。 | 润色 |
| 4 | 配角小目标 | 给工具人配角加一个自己的小诉求 | 加字数 |
| 5 | 环境细致描写 | 感官细节（视/听/嗅/触/味），但必须服务情绪或情节 | 辞藻、加字数 |
| 6 | 环境与情绪绑定 | 环境不是背景板，是情绪的投射或反衬 | 润色 |
| 7 | 世界观细节拆碎 | 把设定拆进场景物件、对话、动作，不大段说明 | 加字数 |
| 8 | 因果链补全 | 把跳跃的因果补上中间环节，让转折不突然 | 润色、盘逻辑 |
| 9 | 时间感放慢 | 写“等待”“犹豫”的时间，不直接跳到结果 | 加字数 |
| 10 | 多角度呈现 | 同一事件，不同角色的反应和解读 | 加字数 |
| 11 | 对话往返 | 把一句直白台词拆成有来有回，加停顿、打断、答非所问。具体执行见「画面感执行纪律」第 3 条。 | 润色、加字数 |
| 12 | 潜台词 | 角色说的和想的不一致，制造张力。具体执行见「画面感执行纪律」第 3、5 条。 | 润色 |
| 13 | 主题呼应 | 用情节或对话点题，但不说教 | 润色 |
| 14 | 伏笔埋设 | 在扩写中自然埋设后续要用的伏笔 | 加字数 |
### 按指令分级推荐​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
| 用户指令 | 优先推荐 | 避免 |
|---------|---------|------|
| 「润色」 | 心理层次、潜台词、因果链补全、主题呼应 | 大段环境、堆辞藻 |
| 「增加辞藻华丽度」 | 感官细节、比喻意象、环境与情绪绑定 | 堆形容词、堆套话 |
| 「单章增加字数」 | 对话往返、时间感放慢、多角度呈现、配角小目标 | 重复信息、无信息环境 |
| 「盘逻辑」 | 因果链补全、伏笔埋设 | 纯辞藻、纯环境 |
| 「这一段太平」 | 冲突升级、潜台词、节奏波形 | 加闲笔 |
### 关键章 vs 过渡章​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
- **关键章节**（高潮、反转、伏笔回收、重要对话）：可往深里扩（心理、潜台词、伏笔）。
- **过渡章节**（主线推进、日常、铺垫）：扩写要克制，避免拖节奏。
### 饱和时的处理​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
用户要求加字数，但 AI 判断本章已饱和时：
- **不得直接加字**，也不得直接拒绝。
- 输出【扩写利弊提示】：说明加字可能带来的好处（如情绪更饱满、人物更立体）与风险（如节奏拖慢、钩子延后）。
- 给出 2-3 个替代方案（如扩写下一章、新增一个场景、只扩写某一处）。
- 由用户选择：仍要加 / 换方案 / 不加。
### 总纲​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
> **加字必须服务情节、人物、氛围、伏笔、主题之一；否则不加。**
### 与现有机制挂接​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
| 扩写方向 | 挂接的现有机制 |
|---------|--------------|
| 人物细节、心理层次 | 人物档案（欲望/恐惧/秘密/弧光 + 语言指纹） |
| 环境细致描写 | 七维「语言」感官细节条 |
| 因果链补全 | 逻辑硬校验「因果链完整」 |
| 对话往返、潜台词 | 对话质量评分（信息密度、潜台词） |
| 伏笔埋设 | 伏笔表 |
| 主题呼应 | 主题档案 |
| 节奏控制 | 七维「叙事」节奏曲线 |
| 防注水边界 | 防注水自查清单、防过度修改 |
