# 人物、世界观与伏笔一致性参考​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

> 版本：v1.4.13

本篇是状态库中「人物状态表、世界观规则、伏笔表」三张表的具体档案模板，配合 `progress-tracking.md` 的滚动摘要与持久化约定使用。

长篇扩写跨轮进行，上下文会被压缩。人物性格、能力、关系、世界观底层规则、伏笔状态是跨轮一致性的生命线，必须在每轮显式维护，并持久化到本次任务目录下的档案文件（与产物同目录）。上下文模糊或缺失时，先回到本文件与对应档案重建一致性基线。

## 1. 人物档案​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

凡主要人物、或次要但反复出场的人物，均登记一张人物卡。建议集中写入任务目录下的 `characters.md`。

| 字段 | 内容 |

维护规则：
- 每章结束，凡本章有状态变化的人物，更新其「当前状态」与「弧光阶段」。
- 校验时对照档案：人物本章的知识、能力、位置、情绪是否与档案一致。
- 角色设定确需变更时，在档案中登记「变更原因 + 章节」，不静默修改。
- 「恐惧」与「秘密」为必填字段（与 SKILL.md 七维「人物」要求对齐），不得留空。
- 「语言指纹」为七维「人物」要求字段，每人固定 2-3 个，用于对话质量评分的「角色辨识度」维度与说话人标注优先级第 4 级。
- 「自我定义」「最怕变成谁」为每个主角、主要配角必填（0b 人物小传阶段校验，填不出则小传不得通过）：自我定义要能被一句台词推翻，「最怕变成谁」要具体到可指认的对象/人设，不得写抽象情绪；「动摇记录」逐章追加，每 5 章至少 1 次「做了正在变成最怕变成的那个人」且角色自知。
- 「Hamartia（致命缺陷）」为每个主角、主要配角必填：缺陷须与高潮灾难构成因果反噬（A 导致 B 发生），不得只写性格标签；详见第 1 节字段表。
- 「救猫咪（Save the Cat）」为每个主角、主要配角出场前三章必填：须写一个微小但能建立读者好感的善举，用于锚定情感；第 1 章主角必须完成此瞬间。
- 「口音/方言」按 SKILL.md「方言与口音控制阀」登记：只记方言类型、等级（L1 词汇点缀 / L2 语气助词，上限 L2）、触发条件；仙侠/玄幻/西幻/科幻及古代题材默认禁用，生僻方言词首次出现须括号注释。
- 启用逐句台词确认模式时，每章结束把该角色已确认台词登记到 `dialogue_log.md`，并更新「语气样本索引」列（覆盖最近 3 条或关键条目），供下一章对照语气一致性。
- 语言指纹应与当前题材扩展包（`references/genres/`）的语言指纹库一致；角色跨题材时，以当前作品主题材为准。

### 主要角色判定标准（每本书通用）​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

满足任一条即算主要角色，必填「自我定义、最怕变成谁」：
1. 出场跨 3 章以上；
2. 有独立动机线（不只是推动主角）；
3. 反复参与关键场景（每 5 章至少出现 2 次）。

非主要角色：可标「本章未立，待补」，不判 ✗；若后续升格为主要角色，须在升格章补填。

**上限规则**：单本主要角色超过 8 个时，作者可指定其中 3–5 个为核心角色，核心角色必填；其余主要角色可标「待补」，不判 ✗。作者指定结果写入 0b 人物小传确认项。

**判定权**：主要角色名单在 0b 人物小传阶段确定，逐章不重判；角色升格时，在状态库登记「升格章」。

**名单可追加（防漏判、防定死）**：0b 确定的是初始名单；后续章节出现新角色，满足三条标准任一，由作者在出现章追加进名单，标注「追加章」，不回溯重判前章。未追加但满足标准的新角色，7.6-3 可标「未入名单，暂不判」，但最多连续 2 章；第 3 章仍不入名单，判 ✗。

| 角色类型 | 语言指纹 | 示例 |

| 剑修 | 短句、少废话、以剑喻事 | “剑不欺人。” |
| 商界大佬 | 慢、稳、话里有话 | “年轻人，急什么。” |

### 资产验收自检（每次 7.6 判定前先过；7.6-2、7.6-3 判定前先过这张清单，任一项不合格，7.6 直接判 ✗，不进对表）​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

人物卡三字段：
- [ ] 自我定义：是一句**可被一句台词推翻**的话，不是标签。（反例：「我是好人」；正例：「我从不欠人情」）
- [ ] 最怕变成谁：具体到**一个人或一种可指认的人设**，不是状态。（反例：「怕失败」；正例：「怕变成我妈那样一辈子为别人活的人」）
- [ ] 动摇记录：有具体事件，不是「有动摇」三个字。
- [ ] 若启用群像/多线模式，核心团队是否覆盖至少 3 个不同的群像功能位？

关系账本：
- [ ] 旧账：具体到**一件事**，不是「关系不好」。（且区分：旧账＝有欠有还；前史＝信息不对称。前史不能长期充当旧账，每 5 章至少一笔真旧账）
- [ ] 期待错位：两边都写，A 以为 B 要什么、B 实际要什么，各能引一句原文或一句可验证的设定。
- [ ] 双方都不知道的：写的是 A 和 B 都不知道、读者能看到的信息；不是「A 知道 B 不知道」（那是前史）。可留空，但填了就要真做到两人都不知道。
- [ ] 始终没说出口的：写的是全书不点破的东西；已确认此栏不在 foreshadowing.md 登记、不进核销流程。
- [ ] 最近一次代价：写的是「谁为这段关系付出了什么」，不是「关系更近了」；填了须具体到一件事，留空合法。
- [ ] 当前状态：一个词或短语，不是一句话。
- [ ] 最近位移章：有位移填章号，无位移留空；不得填「待定」。

任一勾不上，7.6 对应项判 ✗，不进对表。

## 2. 世界观/设定档案​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

用于奇幻、科幻、架空等依赖世界规则的作品。集中写入任务目录下的 `settings.md`，按主题登记。

| 主题 | 设定条目 | 首设章节 | 备注/是否可变 |
|------|---------|---------|--------------|
| 世界基本规则 | | | |
| 地理/地图 | | | |
| 力量/魔法体系 | | | |
| 组织/阵营 | | | |
| 历史/大事记 | | | |
| 社会/经济/文化 | | | |

**系统型设定（`settings.md` 子表，有哪类登哪类）**：三类——力量/等级递进表、经济/资源换算表、组织/权力层级表，分别登记 等级→能力 递进、资源 兑换比、层级→权限 对应关系。

每 10 章跑一次系统校验（**触发点挂接在张力复盘的第 2 个周期执行，见 quality-audit 张力复盘第 10 项；无独立触发机制，勿另行自设周期**），只查：等级递进有无跳级/倒退矛盾、经济换算有无汇率不一、权力层级有无越级行使且无交代。查出问题登记 `settings.md`「设定修订」，并联动 `state/retcon-log.md`：凡修订涉及前文引用，走 SKILL.md 阶段 3.5 影响面回算。

维护规则：
- 底层规则标记为「硬设定」，任何使用不得与其矛盾；确需修改时，在档案登记「设定修订」并说明对既有章节的影响，避免读者察觉。
- 每章引入新设定时登记「首设章节」。
- 世界观规则应与当前题材扩展包（`references/genres/`）的世界观规则模板一致；冲突时，以用户在阶段 0 确认的设定为准，并登记差异。
- 现实元素模糊化处理见 `SKILL.md`「内容安全硬约束」第 7 条。
- **设定条目作废状态机（阶段3.5）**：设定条目状态支持「已作废（被 RT-xxx 替代）」与「悬置（作者决定不回收）」。已作废条目保留不删、带替代条目编号，AI 读取时跳过作废项；推翻既有设定须登记 `state/retcon-log.md` 并回算前文影响面（见 SKILL.md 阶段3.5）。

## 3. 伏笔生命周期管理​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

伏笔不只登记，要管住「埋 → 跟 → 收 → 核销」全周期。

| 伏笔 | 埋设章节 | 技法类型 | 状态 | 计划回收章节 | 实际回收章节 | 核销备注 |
|------|---------|---------|------|------------|------------|---------|

状态取值：待埋 / 待回收 / 已回收 / 标记修正 / 已核销 / **已作废（被 RT-xxx 替代）** / **悬置（作者决定不回收）**。「待埋」＝已登记计划、正文未出现；埋设时改「待回收」并回填实际埋设章。

规则：
- 「技法类型」与细纲【技法标注】、`foreshadowing.md` 三处保持一致，取值：契诃夫之枪 / 草蛇灰线 / 榫卯 / 红鲱鱼 / 其他。红鲱鱼为故意误导读者的假线索，悬疑/反转章节须提前埋设至少 1 个。
- 每章结束，把「应回收而未回收」的伏笔推进回收，或明确标记为保留伏笔并说明。
- 结尾阶段做伏笔清点：登记表中所有「待回收」伏笔必须有结论（回收，或明确悬置并说明原因）。
- 「标记修正」用于设定或伏笔发生变更时留痕，不删历史。
- 「已作废（被 RT-xxx 替代）」用于被新方案取代的伏笔：条目保留不删、带替代条目编号，AI 读取时跳过作废项；作废须登记 `state/retcon-log.md`（见 SKILL.md 阶段3.5）。
- 「悬置（作者决定不回收）」用于作者明确决定不回收的伏笔，须在核销备注注明。
- 伏笔回收后须推进到「已核销」状态，不得长期停留在「已回收」。

## 4. 跨部伏笔表（系列作品专用）​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

系列作品在 `series_foreshadowing.md` 中单独维护跨部伏笔。单部、短篇不建此表。

| 伏笔 | 埋设部/章 | 技法类型 | 计划回收部/章 | 实际回收部/章 | 状态 | 备注 |
|------|----------|---------|--------------|--------------|------|------|
| 例：玉佩刻纹 | 第1部/第3章 | 草蛇灰线 | 第4部/第20章 | — | 待回收 | 跨部 |

规则：
- 「技法类型」与本部伏笔表、细纲【技法标注】保持一致，取值同上。
- 跨部伏笔只登记在 `series_foreshadowing.md`，本部伏笔表只记本部内伏笔。
- 本部伏笔表里，跨部伏笔标「跨部，详见系列状态库」。
- 每部开头（部初始化）时，自动列出「本部应回收的跨部伏笔」。
- 结尾阶段做跨部伏笔清点：所有「待回收」跨部伏笔必须有结论。
- 状态取值与本部伏笔一致（七值见上节「伏笔表」，不再复列）。

## 5. `dialogue_log.md` 字段登记​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌

逐句台词确认模式专用档案，集中写入任务目录下的 `dialogue_log.md`。每条目结构如下：

| 字段 | 内容 |
|------|------|
| 条目ID | `D-章节-句序`，章节与句序补零三位，例如 `D-012-003` |
| 章节 / 场景 / 句序 | 记录台词在文中的位置 |
| 角色 | 说这句台词的角色名 |
| 上下文功能 | 推进情节 / 揭示性格 / 制造冲突 / 埋设伏笔 / 回收伏笔 |
| 4 个推荐及标注 | 记录 A/B/C/D 选项、风格、潜台词 |
| 用户选择 / 输入 | 选推荐 / 自行输入 / 跳过 / 自动 |
| 最终台词 | 定稿台词文本 |
| 对话评分 | 五维评分与均分 |
| 回改记录 | 事后逐句改的记录（时间、原句、新句、影响评估） |
| 是否影响状态库 / 摘要 | 是 / 否，若“是”注明受影响条目 |
| 状态 | 已确认 / 待重写 / 已核销 |

维护规则：
- `dialogue_log.md` 以**追加**为主，可回改、可核销，不删除历史条目。
- `characters.md` 的「语气样本索引」列只存最近 3 条或关键条目 ID / 锚点，不存全文；全文以 `dialogue_log.md` 为唯一权威来源。
- 每章结束，把本章确认的台词登记到 `dialogue_log.md`，并同步更新相关角色的「语气样本索引」。
- 自动续写「事后逐句改」若影响剧情走向、人物关系、伏笔状态，需在对应条目登记「待重写标记」，并在状态库 / 摘要中登记变更（不物理回滚）。
- 语言指纹样本可反向写回 `characters.md` 的「语言指纹」列，用于后续台词推荐与对话质量评分。
