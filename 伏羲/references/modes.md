## 自动续写模式​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
当用户说出以下指令时，触发自动续写模式：
- “自动写 N 章”
- “一口气写到第 X 章”
- “连续写 5 章不中断”
### 执行规则​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
1. 在单轮内连续执行 N 个章节的完整循环（提取 → 细纲 → 正文 → 校验 → 更新状态库 → 更新摘要）。
2. **强制暂停点**：每完成 5 章，必须强制暂停一次，输出【自动续写阶段报告】，包含：本阶段进度（字数 vs 目标）、主线推进状态、是否有提前收尾迹象。用户确认后才能继续下一批。此外，逻辑硬校验触发自动重写、发现应回收而长期未回收的伏笔、或状态库出现无法自动解决的矛盾时，也必须暂停。
3. 未触发暂停点时，不请求确认，直接进入下一章。
4. 每完成一章，在输出中简要标注「第 X 章完成，累计 Y 字」即可。
5. 自动续写模式下，仍须遵守每轮正文不少于 2000 字、不超过 5000 字的约束（**`literary` 模式上限放宽至 8000，与引擎基线一致**）；单轮连续多章时，总字数可突破单章上限，但不得一次性输出全文。七维自评表可简化为一行，但逻辑硬校验表必须每章输出且 7 项逐项打钩；若任一不通过，必须暂停重写。不允许连续写超过 5 章不暂停。
6. 若逐句台词确认模式已开启，自动续写改为「AI 按角色档案代选 + 用户事后逐句改」。
7. 事后逐句改时，按「逐句台词确认模式 · 与自动续写模式的兼容」执行评估与「待重写标记」登记，再重新推进。
## 输出格式​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
每轮输出必须包含（下列项按标注的触发条件出现）：
1. **【进度面板】** 当前字数 / 目标字数 / 已完成章节 / 待完成章节
   - 进度健康度：已完成 X 万字 / 目标 Y 万字（Z%）。若 Z < 95% 且本章出现收束性情节，标记【警告：疑似提前收尾】。
2. **【状态库变更】** 本章新增或修改的人物、时间线、伏笔、主线支线、世界观规则
3. **【滚动摘要更新】** 若触发摘要生成，输出新摘要；否则写「无」
4. **【本章细纲】** 3-5 个场景
5. **【正文】** 按细纲展开（逐句确认模式下为片段式推进）
6. **【台词提案卡】**（若逐句台词确认模式已开启，穿插于正文生成过程中）
7. **【台词确认历史】**（若逐句台词确认模式已开启）
8. **【写后校验报告】** 含【本章七维自评表】（语言 7.1–7.4 各出判定；另附【7.5 情节张力】六项实测表与【7.6 冲突层级】七项实测表，逐条 ✓/✗；另附【7.6-8 叙事技法】三项质量标记：不可靠叙述者 / 反讽 / 视角锁定）与硬校验表格；流水线产物齐备：**闸1跨章衔接审计表**（9项✓/✗）、**场景快照**（模块A各行+章末接口）、**钩子台账更新**（触碰/新增登记）、**回归测试结果**（全部生效断言通过/失败）；其后附【投稿前自查报告】（按七维「投稿前自查协议」逐项打勾，列问题与修正动作）
8.5 **【自动精修报告】**（仅自动精修开启时出现）含精修诊断、方案、对照说明
9. **【台词自查报告】**（若逐句台词确认模式已开启，每章末输出）
9.5 **【本章执行回执】**（分两档：轻量每章出，全量每 5 章出）

   **A. 轻量回执（每章必出，缺此表视为本章未完成）**

   【本章执行回执 · 轻量】
   闸1（连续性）：X/9 ✓ ｜ 口径闸：X/6 ✓ ｜ 漏项：无 / 列出来
   七维：语言✓ 叙事✓ 人物✓ 结构✓ 思想✓ 风格✓ 商业✓（✗ 标哪项）
   过渡章：是/否 ｜ 不可偏离项：未触碰/触碰（列哪条）
   职业质感：有 / 本章无（连续 X 章无）
   诗学判断：无 / 有（类型｜作者｜呼应章节） / 回收（来源第X章｜方式）
   扩展神调用：无 / X次（谁｜过审 / 打回：R几＋原因）
   安全锁判定：红线四条全过 / 打回 R几（引用 router.md 条款号）；本章为缓冲章 → 补记 R5（纯水/断线/连坐）判定与连写第 X/2 章；台词另记 T1/T2/T3 与空转熔断：全过 / ✗ 引原文并记改后句

   - 七行以内，十几秒填完。
   - **「漏项」栏每章必填，不许空**。发现哪项该做没做，如实写，不许填「无」除非真无。
   - 漏项不为「无」时，在【下一步】提示作者「本章漏执行 X 项，是否补」。

   **B. 全量回执（每 5 章出一次；第 5、10、15…章必出，其余章可跳过）**
   | 检查项 | 状态 |
   |---|---|
   | 七维（语言/叙事/人物/结构/思想/风格/商业） | 逐项 ✓/✗，✗ 标哪项 |
   | 闸1（连续性九项） | X/9 ✓ |
   | 口径闸（六项） | X/6 ✓ |
   | 闸2 硬红线 | 通过 / 命中哪条 |
   | 细纲确认 | 手动已确认 / 自动续写自检四项✓ / 跳过 |
   | 不可偏离项 | 未触碰 / 触碰（列哪条） |
   | 过渡章 | 是 / 否（是则标豁免了哪几条） |
   | 能力调用检查 | 用到 X / 本章无 / 不启用（C 档题材） |
   | 关系标注 | 标了几场 / 未标原因 |
   | 最近一次代价 | 填了 X 对 / 留空 |
   | 诗学执行 | 本章标注X场 / 写诗X首 / 呼应已标X处 / 已兑现X处 / 到期未兑现X处 / 未标原因 |
   | 扩展神调用（谁／点子卡过审与否） | 本章无 / 调X次（过审／打回：R几） |
   | 安全锁判定（引用红线条款号） | 红线四条全过 / 打回 R几；缓冲章另记 R5 三项与连写计数 ｜ 台词 T1/T2/T3 ＋ 空转熔断（✗ 须引原文） |
   | 漏项 | 无 / 列出本章漏执行的所有项 |

   **回执规则**：
   1. 轻量回执**每章必出**；全量回执**每 5 章必出**。轻量缺表视为本章未完成，全量缺表视为该 5 章单元未闭合。
   2. **「漏项」一栏不许填「无」除非真无**。AI 自检发现哪项没执行，必须填进「漏项」，不许隐瞒。
   3. **回执不是判定**，是自检收据。填了不改变闸1、闸2 的判定结果，只让作者一眼看见执行情况。
   4. **作者可只看回执**：平时只看轻量七行，每 5 章看一次全量十四项。
   5. **全量回执不重复轻量**：出全量的那一章，轻量可省略，只出全量。
10. **【下一步】** 询问用户是否继续
> **每章第 10 步输出清单（缺一不得报「已完成」）**：正文 + 场景快照 + 钩子台账更新 + 闸1审计表 + 回归测试结果 + **本章执行回执（轻量每章；全量每 5 章）**；缺任一项视为未完成，补齐后再输出【下一步】。
> 若处于自动续写模式，按自动续写模式规则精简输出；未触发暂停点时，可不逐章输出完整校验报告，但须在暂停点汇总。
> 第 1 章完成后，【下一步】必须附加自动精修提醒：
> 「检测到本 skill 支持自动精修。是否开启？开启后每章将自动执行精修流程，字数增幅受控（不超过 20%）。默认关闭。回复'开启自动精修'即可启用。」
## 查询与导出命令​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
- 用户说「查询人物 XX」→ 输出该人物完整状态卡。
- 用户说「查询伏笔」→ 输出伏笔表。
- 用户说「查询摘要」→ 输出当前滚动摘要树（低级+高级）。
- 用户说「查询题材」→ 输出当前已加载的题材扩展包与题材清单。
- 用户说「导出状态库」→ 输出完整状态库 Markdown，方便保存。
- 用户说「导出摘要」→ 输出完整滚动摘要 Markdown。
- 用户说「更新状态库：……」→ 按用户指令修改，并输出变更。
- 用户说「更新摘要：……」→ 按用户指令修改摘要，并输出变更。

## 2500字小循环工作台模式​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
### 触发条件​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
当用户说「开始小循环」「写 2500 字」「盘逻辑」「润色这一段」「下一轮」时，进入本模式。
### 核心流程（每轮严格按顺序，不得跳步）​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
1. **【本轮细纲】**：根据状态库和上一轮结尾，输出本轮 2500 字细纲：3-5 个场景，每个场景写核心事件、出场人物、逻辑钩子。
2. **【草稿】**：按细纲生成 2500 字左右正文。尽量一次输出完成；若单次不足，可要求「继续草稿剩余部分」，但本轮总字数控制在 2300-2800 字之间。
3. **【台词确认】**（逐句台词确认模式默认启用，与第 2 步【草稿】交替进行）
   - 草稿推进到角色开口处即暂停，输出【台词提案卡】，确认后嵌入，再继续草稿。
   - 每句台词确认前，提醒用户上一句角色为什么说这个台词，拆成场景功能、角色动机、伏笔/信息三个维度。
   - 用户确认后嵌入正文，继续下一段。
   - 旁白、心理、留白、心声不询问。
   - 用户可说「本章自动」退出逐句确认。
4. **【逻辑盘查】**：对照状态库、滚动摘要、前文，逐项检查——人物状态是否一致、时间线是否矛盾、伏笔是否误用/遗忘、因果链是否完整、视角是否一致、设定是否一致、是否有注水或重复。输出表格：| 检查项 | 结果 | 问题位置 | 修正建议 |
5. **【润色】**：只针对逻辑盘查通过或已修正的段落润色，分三轮：
   - 第一轮：修语病、句式、标点。
   - 第二轮：补细节（动作、心理、感官），但不新增剧情。
   - 第三轮：统一文风，对照文风锚点。
   输出【润色对照】：原文→改后，关键修改不超过 10 条。
6. **【状态库更新】**：根据本轮内容，更新人物状态表、时间线、伏笔表、主线支线进度、世界观规则，输出【状态库变更】。
7. **【滚动摘要】**：按「滚动摘要机制（R 体系）」章节执行——每完成约 2500 字生成一段 100-150 字摘要（R1、R2……），每积累 4 段合并为一段 200-300 字高级摘要（H-R1、H-R2……），已合并的 R 摘要标记「已归档」。
8. **【下一轮接口】**：输出本轮结尾与下一轮的衔接点，并询问用户是否接受本轮，或需要局部重写。
### 上下文携带规则​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
每轮只读取：状态库精简版；最近 4 段未归档的 R 摘要；最近 1 段 H-R 高级摘要；最近 2500 字全文；本轮细纲。禁止引用更早原文，需要时先查状态库。
### 防过度修改​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
- 润色不得改变核心剧情、人物关系、伏笔状态。
- 单轮润色后字数增幅不超过 15%。
- 同一段文字最多润色 3 轮，第 3 轮后必须定稿或标记「待人工」。
- 逻辑盘查不通过时，先修正逻辑，再润色。
### 输出格式​‌‍‌‌‌​‌​​​‌​‌‌​‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​‌‌‌‌​​‌​​​‌‌‌‌​‌​​‌‌​‌​​​‌‌‌​​‌‌‌‌​‌‌‌​​‌​‌‌​​​‌‌​‌‌​‌‌​​​​‌‌‌​‌​​​‌​‌‌​​​‌‌​‌​​​​‌
每轮结束必须输出：
1. 【本轮进度】字数、场景数、累计字数
2. 【逻辑盘查报告】
3. 【润色对照】
4. 【状态库变更】
5. 【滚动摘要更新】有则输出，无则写「无」
6. 【下一轮细纲预告】
7. 【询问】是否接受本轮？需要重写哪部分？
8. 【台词确认历史】（逐句确认模式下，本章末输出）
9. 【台词自查报告】（逐句确认模式下，每章末输出）
