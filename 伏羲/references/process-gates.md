# 强制门禁总则

> 本文件为阶段推进的唯一判据。任何其他文件（含 SKILL.md、workflow.md、modes.md、series-parallel.md）与本文冲突时，以本文为准。
> 生效范围：本 skill 下所有小说项目，含新书、续写、续建、返工、重走。

1. 阶段状态初始全为“未完成”。只有具备以下证据之一才可改状态：文件路径、文件原句、脚本输出、用户确认原话。
2. 禁止用“已做／基本做／相当于做了”代替证据。无证据一律判“未完成”或“无法验证”。
3. 阶段顺序（14 阶）：种子 → 首发门禁 → 0a → 0a+ → 0b（前置自动校验：world-rules.md 是否存在） → 0b附 → 0c-0 → 0c → 0d → 细纲 → 正文 → 三道闸（三闸＝闸1/闸2/闸3，定义见 workflow.md；**闸1 之前须先过场级闸与落地闸八问**，见 `references/prose-rules.md`；本章实际执行含场级闸、落地闸、口径闸与两项回执，见下方状态表「三道闸」行） → guard.py → 0d+。不得跳阶。进入 0b 前，无需用户口令，系统自动检查文件，不存在则按 workflow.md【信使接力协议】原样输出【盘古】复制框并阻断等待。
4. 确认口令必须精确匹配，少一个字不算：
- 种子阶段：用户回“种子确认”
- 首发门禁：用户回 “1”、“2” 或 “3”（单个数字；去空白后整段等于其一才通过）
- 0a：用户回“题材规模确认”
- 0a+：用户回“模式确认”
- 0b：用户回“方案确认”
- 0b附：用户回“资产确认”
- 0c-0：用户回“schema确认”
- 0c：用户回“状态库确认”
- 0d：用户回“确认后开始续写”
- 细纲：用户回“细纲通过”
- 正文：用户回“细纲通过”（与细纲同一口令；未获该口令，正文一字不得写出）
- 三道闸：用户回“闸通过”（“闸通过”覆盖下方状态表「三道闸」行的全部判据项：**场级闸＋落地闸八问**／闸1／口径闸／闸2／文本层回执／对话评分；闸3 仅润色稿触发，未触发记「不适用」）
- guard.py：用户回“guard通过”，或用户书面裁决为例外（须写明“裁决例外”并注明理由）
- 0d+：用户回“冷启动通过”
5. 每阶段结束必须输出《阶段回执》，字段固定：阶段｜要求｜产物路径或原句证据｜状态｜缺什么｜等待的确认口令。未输出回执，不得进入下一阶段。
6. 未获确认口令前，禁止：创建生效 state-schema.md、写正文、写细纲后直接写正文、自动推进下一阶段、把草案写成定稿。
7. 例外条款只能收紧，不得扩大。AI 不得自行解释例外；用户未明确选择“先写后补”，不得启用该例外。
8. 任何阶段若发现前序阶段状态为“未完成”，必须停止并输出《阻断清单》，不得继续。
9. 每章正文写完后，必须跑场级闸、落地闸八问、三道闸、跨章重合扫描和 guard.py； FAIL 必须重写或由用户书面裁决为例外，不得静默通过。
10. 任何**新增的校验闸／规则**建立后，必须对**此前已通过旧闸的章节补跑**，不得只用于新写的章；回溯改稿后，该章此前拿到的确认口令随之作废，须按现行正文重新确认。
11. 任何**口径变动**（称谓、名字、年龄、艺名、行规类）必须四处同步：`constraints/author-decisions.md`（新 AD）、`constraints/regression-tests.md`（R 项断言）、`characters`（人物卡）、**方案级文件与 `settings.md`（制度底座）**——设定库与约束库之间没有自动比对，落盘前 grep 同义词兜底。
12. 本文件优先于 workflow.md 中任何宽松表述。
